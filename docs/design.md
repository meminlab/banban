## 0. 방향

**"구조는 하나, 테마는 셋. 흰 바탕에 큰 숫자, 색은 테마마다 한 가지만."**

| 원칙 | 뜻 | 화면에서 |
|---|---|---|
| 10초 안에 | 열자마자 이번 달 숫자, 한 번 눌러 입력 | 홈 첫 화면에 남은 돈. ＋ 버튼은 **모든 탭의 탭바 가운데** 같은 자리. 입력은 금액 키패드부터 |
| 숫자가 주인공 | 금액은 가장 크고 굵고, 자릿수가 세로로 맞는다 | 금액은 항상 `tabular-nums`, 라벨은 작고 연하게. 홈 남은 돈 36px, 입력 금액 40px |
| 구조는 하나 | **화면 배치·컴포넌트·글자·간격은 모든 테마가 같다** | 테마는 색 토큰과 "강조 표현 토큰"(카드 모서리·여백·그림자·요약 카드 바탕)만 바꾼다 |
| 색은 한 가지 | 테마마다 **포인트 색 1개 + 무채색 단계.** 포인트 색은 "누를 수 있는 것·선택된 것"에만 | 카테고리 아이콘은 모두 회색 원. 사람 색(멤버 색)은 "누가 얼마나" 막대에만. **일정 색(1.6)은 일정 칩·일정 행 원에만** (v1.6) |
| 의미 색은 아껴서 | 수입·저축·음수 색은 **금액 숫자에만** | 배지·아이콘 원·안내 상자에는 의미 색을 칠하지 않는다 |
| 색은 거들 뿐 | 의미는 글자·기호·아이콘으로 먼저 전한다 | 음수는 `−` 기호 + 빨강, 선택은 체크 아이콘 + 색 |

벤치마크(모아불리·뱅크샐러드)는 수준만 참고하고 색·문구·로고·아이콘은 가져오지 않았다. 테마 후보 탐색 기록은 `docs/design-explore/`.

### 0.1 테마 3종

| 테마 | 코드 이름 (`data-theme`) | 한 줄 | 포인트 색 | 강조 표현 |
|---|---|---|---|---|
| **클린 (기본)** | `clean` | 은행 앱처럼 정돈된 흰 화면 | 초록 `#007F55` | 카드가 화면 끝까지(좌우 여백 0, 모서리 0), 구역은 회색 띠 12px, 그림자 없음 |
| 베리 | `berry` | v1.1 그대로의 차분한 무채색 화면 | 베리 `#A23B72` | 회색 바탕 위 흰 카드(좌우 16, 모서리 16, 옅은 그림자) |
| 포근 | `cozy` | 둘이 함께 쓰는 따뜻한 화면 | 코랄 `#C44536` | 살구빛 바탕, 큰 라운드(카드 24·버튼 16), 요약 카드에 연한 포인트 바탕, **사람별 아바타 색** |

- 사용자가 설정에서 고르고, **사용자별로 저장**한다(같은 가계부라도 사람마다 다른 테마 가능). 선택 기능 개발은 별도 이슈.
- 라이트/다크는 테마와 별개로 기기 설정(`prefers-color-scheme`)을 따른다. 테마 3종 × 라이트/다크 = 6벌.
- 코드 이름은 확정이다(나중에 rename 하지 않는다). 화면 이름은 "클린 / 베리 / 포근".

> **결정 기록 (디자인, 2026-11-06) — 기본 테마 = 클린(`clean`).** ① 지금 운영 중인 앱의 포인트 색이 초록(`#1f6f5c`)이라 기존 사용자에게 바뀜이 가장 적다. ② 클라이언트가 처음 요청한 "더 깔끔하고 금융 앱다운 느낌"에 가장 가깝다. ③ 그림자·모서리가 없어 가장 가볍고, 다른 두 테마로 바꿔도 구조가 같아 어색하지 않다.

> **결정 기록 (디자인) — 공통 구조는 세 안에서 이렇게 골랐다.**
> - 입력: **B의 키패드 입력 + 빠른 금액 버튼**(클라이언트 지정). 세부 항목은 B의 요약 행(누르면 바텀시트), 세그먼트는 A의 상자형(더 크고 분명함).
> - 홈 요약 카드: A의 구성(월 이동 → 남은 돈 → 수입·지출·저축 3칸). 포근은 카드 바탕만 연한 포인트 색(C).
> - "누가 얼마나": C의 한 줄 나눔 막대 + 사람별 행. 막대 색은 테마별 멤버 색.
> - 헤더: 가계부 전환 버튼을 **회색 알약 버튼**(멤버 아바타 묶음 + 가계부 이름 + `ChevronsUpDown`)으로 — 누를 수 있다는 게 보이게(5.18). 아바타 바탕은 클린·베리는 회색, 포근만 사람별 색.
> - 탭바: C처럼 **＋를 탭바 가운데**에 고정(모든 탭에서 같은 자리). v1.1의 떠 있는 ＋ 버튼은 없앤다.
> - 뺀 것: B의 "지난달보다 덜 썼어요"(지난달 비교는 명세에 없는 기능), B의 카테고리 여러 색 막대(v1.1 "그래프 다색 금지" 유지), C의 고운돋움 제목 글꼴(글꼴 1종 유지, 번들 크기), C의 주머니 목표 안내(명세에 없는 기능). 필요하면 다음 단계에서 기능으로 제안한다.

## 1. 색

### 1.0 토큰 구조

토큰 이름 `color.xxx` → CSS 변수 `--color-xxx`. 세 층으로 나눈다.

| 층 | 무엇 | 테마마다 다른가 |
|---|---|---|
| 테마 색 | 바탕·글자·선, 포인트 색, 요약 카드, 멤버·아바타 색, 저축 색 | 다름 (1.1 표) |
| 공통 의미 색 | 수입 `income`(v1.4: = `primary-strong`), 음수 `negative`, 위험 `danger`, 지출 `expense`(= `text`) | 같음 (1.2 표) |
| 강조 표현 | `card-gutter`·`card-radius`·`control-radius`·`card-shadow` | 다름 (1.5 표) |

컴포넌트 CSS는 **토큰만** 쓴다. 테마 이름으로 분기하는 CSS(`[data-theme="cozy"] .button {…}`)는 쓰지 않는다 — 분기가 필요해지면 토큰을 하나 더 만든다. 이게 "구조는 하나"를 지키는 규칙이다.

### 1.4 다크 모드

- 기기 설정 `prefers-color-scheme: dark`를 따른다. 앱 안 라이트/다크 토글은 다음 단계.
- 다크에서는 그림자 대신 `surface` 명도 차이와 카드 `1px border`로 층을 구분한다(클린은 위아래 테두리만).
- `<meta name="theme-color">`는 헤더 `surface`와 같게: 라이트 `#FFFFFF`(세 테마 공통) / 다크 클린 `#161E1B`, 베리 `#1F1A22`, 포근 `#261C18`. 테마를 바꾸면 JS로 다크 값을 갈아 끼운다.

**다크에서 테마가 구분되게 (v1.3, BANB-33)** — 클라이언트 피드백 "다크에서 클린·베리·포근 차이가 거의 안 느껴짐".
v1.2 다크는 세 테마 모두 바탕·카드가 거의 같은 검정 회색이고 포인트 색은 ＋·저장 버튼 같은 작은 곳에만 있어서, 화면 대부분이 같아 보였다. 그래서 다크에서만 아래 4가지를 바꿨다(라이트는 그대로).

1. **바탕에 테마 빛깔**: `bg`·`surface`·`surface-sunken`·`border`·글자 회색 단계에 포인트 색 쪽 색조를 아주 조금 넣는다. 클린 = 푸른 초록빛 검정, 베리 = 자줏빛 검정, 포근 = 갈색빛 검정. 화면 전체 분위기가 테마마다 달라진다.
2. **요약 카드(`hero-bg`)는 세 테마 모두 포인트 색 바탕**: 클린 짙은 초록 `#123B2A`, 베리 짙은 자주 `#3F1D39`, 포근 짙은 살구 갈색 `#4A2819`. 라벨(`hero-label`)은 밝은 포인트 색. 홈에서 가장 큰 카드라 한눈에 테마가 보인다. 라이트는 지금처럼 포근만 색이 있다.
3. **선택 표시를 진하게**: `primary-soft`(탭 알약·선택 칩 바탕)를 더 진하게, `primary-strong`(그 위 글자·아이콘)을 더 밝게.
4. **빨강(음수·오류)과 떨어뜨리기**: 음수 `#EE8F99`(색상각 354°)에 가깝던 포인트 색을 옮겼다. 베리 `#F08CC0`(329°) → `#EA8CD2`(315°, 자줏빛 베리), 포근 `#FF8A74`(9°) → `#FFA36B`(23°, 살구). 클린 초록은 그대로. 포근 `member-1`·`avatar-1`도 같은 살구 `#F0A27E`로 맞췄다.

> **결정 기록 (디자인, 2026-11-09)** — 다크 3테마 구분은 **새 토큰 없이 기존 다크 토큰 값만 바꿔서** 해결한다. 컴포넌트 CSS는 손대지 않아도 된다(개발 반영 = `src/styles/tokens.css` 다크 값 교체, BANB-35). 다크 포근의 포인트 색은 코랄이 아니라 살구가 된다 — 다크에서 코랄은 음수 빨강과 구분이 안 되기 때문(라이트 포근은 코랄 `#C44536` 그대로).

### 1.6 일정 색 (누구 일정) — v1.6 (BANB-41)

일정 탭에서 "누구 일정인지"를 보여 주는 색이다. 멤버마다 1개 + "함께" 1개. **종류(기념일·약속·정기 지출일·기타)는 색이 아니라 아이콘으로** 구분한다(5.24).

| 토큰 | 누구 | 라이트 | 다크 | 이름 |
|---|---|---|---|---|
| `color.event-together` | 함께 (대상 멤버 없음) | `#FFDCCF` | `#6B3328` | 살구 |
| `color.event-1` | 멤버 1 (참여 순) | `#D6E4FF` | `#26406B` | 하늘 |

- **테마와 상관없이 같은 값**이다(1.2 공통 의미 색처럼 `:root`). 테마는 사람마다 따로 고르므로(0.1), 테마별로 값이 다르면 부부 화면에서 같은 사람이 다른 색이 된다. "민지 = 하늘색"이 두 휴대폰에서 같아야 대화가 된다.
- 세 테마 어디에나 어울리게 **채도 낮은 파스텔**(라이트) / **어두운 같은 색조**(다크)로 골랐다. 테마 포인트 색(초록·베리·코랄)과 같은 색조는 피했다. 2인 가계부가 대부분이라 멤버 1·2는 색맹 유형과 상관없이 가장 잘 갈리는 하늘·노랑 짝이다.
- 칩·원 위 글자·아이콘은 테마 `text` 그대로. 대비(가장 낮은 값): 라이트 11.8 이상, 다크 7.2 이상(4.5 기준 통과, 6벌 모두 계산). 칩 바탕과 카드(`surface`)의 대비는 1.2~1.8로 낮다 → 칩은 글자로 읽히고 색은 거든다(1.3 `member-*`와 같은 판단).
- 색 번호는 가계부 멤버 **참여 순서**(`member-1~4`와 같은 순서). 나간 멤버의 지난 일정은 그 색 그대로 + 이름 뒤 "(나감)".
- **쓰는 곳은 세 군데만**: 일정 탭 칸 칩(5.24), 날짜 시트·목록의 일정 행 원(5.24), 일정 추가의 "누구" 칩 색 견본(5.25). 홈 "누가 썼나" 막대(`member-*`)·아바타(`avatar-*`)는 그대로 두고 바꾸지 않는다(홈 강조 색 1개 규칙 유지).
- 5.23 "한 화면 강조 색 1개"의 예외다: 일정 색은 **강조가 아니라 분류**(누구)여서 채도를 낮춰 포인트 색보다 눈에 덜 띄게 했다. 일정 탭에서도 누를 수 있는 것·오늘·선택은 포인트 색만 쓴다.

> **결정 기록 (디자인, 2026-11-09)** — 일정 색은 **테마 공통 5색 고정**, 종류는 아이콘. 테마별 팔레트는 같은 사람이 휴대폰마다 다른 색이 되는 문제 때문에 쓰지 않는다. "함께"는 회색이 아니라 따뜻한 살구 — 기념일 대부분이 "함께"라 홈 톤("따뜻하게", 클라이언트 보강)과 맞췄다.

- **테마 공통**(`:root`, 1.6 일정 색과 같은 방식). 나무 판은 세 테마 포인트 색(초록·베리·코랄/살구) 어디와도 부딪히지 않는 따뜻한 중간색이라 한 벌로 충분하다. 테마는 판 위의 **포인트 색 표시**(마지막 수 고리·고른 칸·이긴 줄·차례 칸)로 드러난다.
- 흑·백은 무채색 그대로(흑백 대비 16:1). 돌에 색을 입히지 않는다 — 누가 흑인지는 사람 칸의 돌 표시로 본다.
- 대비(계산): 라이트 줄/판 3.35, 흑돌/판 12.6, 백돌 테두리/판 3.9 · 다크 줄/판 3.25, 백돌/판 7.4, 흑돌 테두리/판 3.25 → 그래픽 3:1 통과. 다크 흑돌 자체는 판과 2.2라 **테두리 필수**. 포인트 색/판(마지막 수 고리): 라이트 클린 3.8·베리 4.6·포근 3.7, 다크 클린 3.7·베리 3.7·포근 4.3.
- **사람 표시 = 일정 색(1.6) + 이니셜.** 게임 화면의 아바타 바탕은 `event-1~4`(참여 순)를 쓴다. 1.6 "쓰는 곳 세 군데"에 **같이 놀기 아바타**를 네 번째로 더한다 — 부부가 서로 다른 테마를 써도 "민지 = 하늘"이 두 폰에서 같아야 "누구 차례"가 통한다(`avatar-*`는 클린·베리에서 모두 회색이라 구분이 안 됨).

> **결정 기록 (디자인, 2026-11-09)** — 오목 판은 테마 공통 나무색 1벌 + 흑백 돌, 테마는 포인트 색 표시로만. 차례 표시용 사람 색은 새로 만들지 않고 일정 색(1.6)을 재사용한다.

### 2.3 금액·숫자 표기 규칙

| 규칙 | 예 | 비고 |
|---|---|---|
| 천 단위 쉼표 + `원`, 띄어쓰기 없음 | `1,234,000원` | `toLocaleString('ko-KR')` |
| `원`은 숫자보다 한 단계 작게 | 숫자 36px → `원` 27px(0.75em), 굵기 600 | 숫자가 먼저 읽히게. 17px 이하 금액은 같은 크기 |
| 숫자+`원`은 한 덩어리, 중간 줄바꿈 금지 | — | `white-space: nowrap` (기존 `.money` 유지) |
| **음수 기호는 `−`(U+2212 마이너스 기호)로 통일** | `−52,000원` | 하이픈 `-` 금지. 홈 "남은 돈"의 현재 `-`를 바꾼다 (BANB-9 QA 이관 항목) |
| 음수는 기호 + `color.negative` 둘 다 | `−52,000원`(빨강) | 색만으로 전달 금지 |
| 화면낭독: 기호는 숨기고 단어로 읽힘 | 보이는 것 `−52,000원` / 읽는 것 "마이너스 52,000원" | 아래 마크업 참고 |
| 종류가 섞인 목록·달력에서만 기호 표시 | 지출 `−12,000원` / 수입 `+3,000,000원` / 저축 `500,000원`+저축 배지 | 화면낭독은 "지출 12,000원"처럼 종류 단어로 |
| 라벨이 붙은 합계에는 기호를 붙이지 않음 | "지출 1,234,000원" | 단, 남은 돈·자산 합계가 음수일 때는 `−` |
| 0원 | `0원` (기호·색 없음) | |
| 큰 금액 | 최대 `9,999,999,999원`(13자). hero 금액이 14자 이상(`−` 포함)이면 `amount-hero`(36) → `amount-xl`(28)로 한 단계 줄임 | 기존 `.asset-total__total--long`과 같은 방식 |
| 줄여 쓰기(만·억) | 달력 칸·그래프 축처럼 좁은 곳만. `1.2만`, `35만`, `1.5억` (기존 `compactWon` 규칙) | 줄인 숫자를 누르면 원래 금액이 보여야 하고, 화면낭독은 원래 금액 |
| 비율 | 정수 `%`, 숫자 오른쪽 정렬 | `formatPercent` |
| 날짜 | 목록 그룹 `11월 6일 (목)`, 월 이동 `2026년 11월` | 요일은 괄호 |

음수 금액 마크업 (개발 기준):

```html
<span class="money money--negative">
  <span aria-hidden="true">−</span><span class="sr-only">마이너스 </span>52,000<span class="money__unit">원</span>
</span>
```

> **결정 기록 (디자인, 2026-11-06)**: 음수 기호는 `−`(U+2212)로 통일. 하이픈은 글꼴에 따라 짧고 높이가 달라 숫자와 어긋나 보이고, 화면낭독기가 "하이픈"으로 읽거나 건너뛴다. `−`도 기기마다 "빼기/마이너스"로 다르게 읽으므로, 기호는 `aria-hidden`으로 숨기고 "마이너스"를 글자로 넣는다. 금액 표시 함수(`formatWon`)는 기호만 `−`로 바꾸고, 화면낭독 처리는 금액 컴포넌트가 맡는다.

### 5.18 가계부 전환·추가 동선 — v1.2

문제: 클라이언트가 직접 써 보니 가계부 추가 방법을 찾지 못했다. v1.1까지는 헤더의 가계부 이름(▾)을 눌러야만 목록·추가가 나왔는데, 이름이 제목처럼 보여 버튼인 줄 모른다.

해결: **진입점을 3곳으로 늘리고, 첫 진입점을 버튼처럼 보이게 한다.**

| # | 진입점 | 언제 보이나 | 규칙 |
|---|---|---|---|
| 1 | **헤더 알약 버튼** | 항상(홈·가계부·자산 탭) | 5.6. 회색 알약 + 아바타 + 이름 + `ChevronsUpDown`(위아래 화살표 = "바꿀 수 있음"). 누르면 전환 시트 |
| 2 | **전환 시트의 "가계부 추가" 카드 2장** | 시트를 열 때마다 | 목록 아래 머리 "가계부 추가" 13/700 → 카드 2장 나란히: [`BookPlus` 새로 만들기 / 이름만 정하면 바로 시작] [`Ticket` 초대코드로 참여 / 받은 코드나 링크로]. 카드: 테두리 1.5px `border`, `radius.lg`, 안쪽 14, 아이콘 상자 36 `primary-soft`/`primary-strong`. 그 아래 텍스트 버튼 `Settings2` "가계부 관리" |
| 3 | **설정 › 가계부 관리** | 설정 맨 위 | 설정의 첫 묶음을 "가계부"로: 행 "가계부 관리 · 2개" → 하위 화면 |
| + | **홈 안내 카드** | 가계부가 1개뿐일 때 | 홈 맨 아래 카드: [`BookPlus` 상자] "가계부를 더 만들 수 있어요" / "부모님 용돈, 내 개인 지출처럼 따로 볼 돈은 가계부를 나눠 보세요. 최대 5개." + 보조 버튼 "가계부 추가"(→ 전환 시트를 연 상태). 오른쪽 위 `X`로 닫으면 다시 안 보임(사용자별 저장) |

**전환 시트** (제목 "내 가계부 2/5"): 행 높이 64, 지금 보는 가계부는 `primary-soft` 바탕 + `CircleCheck` + 보조 줄 "멤버 2명 · 지금 보는 중". 5개가 차면 추가 카드 2장을 비활성(`surface-sunken`/`text-weak`)으로 두고 아래 "가계부는 최대 5개까지 참여할 수 있어요" 13 `text-sub`.

**가계부 관리 화면** (설정 › 가계부 관리):
- 머리 "내 가계부 2/5" → 가계부 목록(행 64: 첫 글자 원 + 이름 + "멤버 N명 · 내가 만듦/참여함" + `ChevronRight`, 지금 보는 것은 "지금 보는 중" 주 배지).
- 목록 아래 보조 버튼 2개 나란히: `BookPlus` 새로 만들기 / `Ticket` 코드로 참여. 안내 한 줄 "가계부는 1인 최대 5개. 나가기는 각 가계부를 눌러서."
- 가계부 행을 누르면 그 가계부의 상세: 이름·멤버 수·만든 날 + "이 가계부로 전환"(주) + "가계부 나가기"(위험 외곽 → 확인 창).
- 같은 설정 화면 아래 묶음은 "설정 (지금 보는 가계부: 우리집 가계부)" — 이름·멤버·초대·카테고리·주머니가 **어느 가계부에 대한 것인지** 제목에 밝힌다.

> 결정 기록 (디자인): 탭바에 "가계부 목록" 탭을 따로 두지 않았다. 매일 쓰는 동작이 아니라서 자리를 차지할 이유가 약하고, 헤더 알약 + 시트 카드 + 설정 3곳이면 "어디서 찾든 걸린다". 가계부 1개 사용자에게만 홈 안내를 보여 이미 여러 개 쓰는 사람은 방해하지 않는다.

| 이력 없는 달 | 점·선·월 라벨 모두 비운다(앞쪽부터 빈 칸). 이력이 1달뿐이면 점 1개 + "다음 달부터 추이가 보여요" 13px `text-weak` |
| 누름 | 월 라벨 칸(폭 1/6, 높이 44 이상)을 누르면 그 달이 선택되어 위 값이 바뀐다. 화살표 키로도 이동 |
| 작은 추이 (홈) | 72×36, 선 2px, 점은 선택한 달 하나만(7px), 라벨·축 없음. 카드 전체가 버튼이라 따로 누르지 않는다. 장식이므로 `aria-hidden`, 대신 카드 `aria-label`에 "지난달보다 364만 원 늘었어요"를 넣는다 |
| 구성 막대 | 종류별 행: 아이콘 18 `text-sub` + 이름 15 + 금액 15/700 + % 13 `text-sub`, 아래 6px 막대(`chart-track` 위 `chart-bar`, 길이 = 비율, 최소 1%). 큰 순서대로. 총자산 0이면 % 열과 막대를 숨긴다 |
| 화면낭독 | 추이 그래프는 `role="img"` + `aria-label="최근 6개월 순자산, 6월 1억 9,824만 원부터 11월 2억 650만 원까지"`, 그 아래 월별 값 표를 `sr-only`로 둔다 |

> **결정 기록 (디자인, 2026-11-06) — 월별 추이는 막대가 아니라 선.** 순자산은 몇 억 위에서 달마다 1~2%씩 움직인다. 막대는 0부터 그려야 정직한데 그러면 6개가 같은 높이로 보이고, 0을 자르면 막대 길이가 거짓말이 된다. 선은 범위를 좁혀도 왜곡이 아니라서 "늘었나 줄었나"가 한눈에 보인다. 정확한 값은 그래프 위 한 줄 + 전월 대비 숫자가 맡는다.

### 5.21 증감 표기 (▲▼) — v1.2

| 경우 | 보이는 것 | 색 | 화면낭독 |
|---|---|---|---|
| 늘었음 | `지난달보다 ▲ 3,640,000원` | 라벨 `text-sub`, ▲와 금액 `delta-up`(= `income`) 600 | "지난달보다 3,640,000원 늘었어요" |
| 줄었음 | `지난달보다 ▼ 1,670,000원` | 라벨·▼·금액 모두 `delta-down`(= `text-sub`) 600 | "지난달보다 1,670,000원 줄었어요" |
| 같음 | `지난달보다 변동 없음` | `text-sub` | 그대로 |
| 비교할 달 이력 없음 | `지난달보다 –` | `text-sub` | "지난달 기록이 없어요" |

- 금액에는 `+`/`−`를 붙이지 않는다 — 방향은 ▲▼가 맡는다(`−`는 "음수 값" 전용). ▲▼는 11px, `aria-hidden`.
- 라벨: 홈 카드 "지난달보다", 자산 탭 순자산 카드 "지난달 말보다". 지난달을 보고 있으면 "9월 말보다".
- 증감은 **순자산에만** 쓴다(1단계). 자산 하나하나·부채에는 표시하지 않는다.

> **결정 기록 (디자인, 2026-11-06) — 늘면 파랑, 줄면 회색. 빨강은 안 쓴다.** 주식 앱의 "오르면 빨강, 내리면 파랑" 관습은 이 앱의 "빨강 = 음수·오류"와 정면으로 부딪힌다. 반대로 "줄면 빨강"은 매달 카드값이 빠지는 평범한 감소에도 경고처럼 보인다. 그래서 늘어난 것만 수입과 같은 파랑으로 가볍게 칭찬하고, 줄어든 것은 중립 회색으로 둔다. 색 없이도 ▲▼와 문장으로 뜻이 전달된다.

### 5.23 단순화 규칙 — v1.4 (BANB-35)

클라이언트 피드백 "UI가 조금 복잡함, 더 단순하게"를 반영해 클라이언트가 확정한 규칙이다. 시안·전후 비교: `docs/screens/simplify/` (`README.md`, `simplify.html`, `pair-*.png`). 5.3·5.4·5.15·5.22와 다르면 이 절이 우선한다.

**공통 규칙 3가지**
1. **한 화면에 강조 색 1개** = 테마 포인트 색. 금액 중에는 수입·증가(▲)만 `primary-strong`(1.2). 저축 보라·청록, 수입 파랑은 쓰지 않는다. 빨강은 음수·오류에만.
2. **카드 안 정보 3줄 이내.** 기본형 = 라벨 / 큰 숫자 / 한 줄 요약. 막대·그래프 카드는 제목 / 그림 / 한 줄. 넘치는 정보는 목록이나 하위 화면으로 보낸다.
3. **꼭 필요하지 않은 라벨·구분선·보조 문구 제거.** 값만 봐도 아는 라벨, 묶음 제목, 계산식·안내 문장, 카드 안 구분선을 쓰지 않는다. 묶음은 여백(12)으로만 나눈다.

**헤더**: 가계부 전환 알약은 이름 + `ChevronsUpDown`만(멤버 아바타 없음, 5.6·5.18의 아바타를 뺀다).

**월 이동 줄 (홈·가계부)**: 카드가 아닌 `bg` 위 한 줄(높이 48), `ChevronLeft` "11월" `ChevronRight` 17/700. **올해는 연도를 쓰지 않고**, 다른 해만 "2025년 11월".

**홈** (위 → 아래)
1. 월 이동 줄.
2. **우리집 순자산 카드** — "우리집 순자산" + `ChevronRight` / `xl` 금액 / 증감(5.21). 작은 추이 그래프는 뺀다(자산 탭에 있음). 카드 전체가 자산 탭 버튼.
3. **이번 달 카드** — "11월 남은 돈" / `hero` 금액 / 한 줄 "수입 4,200,000 · 지출 2,915,500 · 저축 500,000"(14 `text-sub` 라벨 + 700 숫자, `원` 생략, 수입 숫자만 `primary-strong`). 계산식 문구("남은 돈 = …")는 쓰지 않는다. 360px에서 한 줄을 넘으면 저축 항목부터 다음 줄로(최대 2줄).
4. **누가 썼나** — 제목 + 오른쪽 이달 지출 합 / 나눔 막대 / 한 줄 범례(점 + 이름 + 금액). %는 쓰지 않는다. 멤버 1명이면 숨김.
5. 어디에 썼나 → 최근 내역 (5.22 그대로, 같은 3줄 규칙).

### 5.38 영수증 줄 (방해 줄) — v1.9

## 6. 접근성 체크리스트

- [ ] 누르는 영역 최소 44×44px (주 버튼·입력 48px). 작은 아이콘도 감싸는 버튼은 44.
- [ ] 키보드 포커스가 항상 보인다(`:focus-visible` 2px `focus` 링). 링을 지우는 `outline: none` 금지.
- [ ] 색만으로 의미 전달 금지: 음수 `−`+단어, 선택 `Check`, 오류 아이콘+문장, 수입·지출 기호/라벨, 활성 탭 알약+굵기, 저축 배지.
- [ ] 글자 대비 4.5:1, 큰 글자·테두리·포커스 3:1 (1.3 표). 새 색 조합은 표에 추가하고 계산한다.
- [ ] 아이콘만 있는 버튼에 `aria-label`. 장식 아이콘은 `aria-hidden`.
- [ ] 금액은 화면낭독기가 "마이너스 52,000원", "지출 12,000원"처럼 의미대로 읽는다.

- [ ] `prefers-reduced-motion` 존중.

## 7. 문구 톤

- 해요체, 짧게. "~하시겠습니까?" 대신 "~할까요?".
- 탓하지 않기: "잘못된 입력입니다" → "금액을 숫자로 적어 주세요".
- 둘이 함께 쓰는 앱: "우리", "둘이" 같은 말을 홈·빈 화면에서 가볍게 쓴다(설정·오류 문구에서는 쓰지 않는다).
- (v1.6) **일정·홈 함께한 날 카드는 해요체로 한 단계 더 따뜻하게** — 숫자만 던지지 않고 문장으로: "함께한 지 1,977일째예요", "결혼기념일까지 5일 남았어요", "오늘은 결혼기념일이에요", "아직 일정이 없어요. ＋로 첫 일정을 남겨 보세요". 금액 화면(가계부·자산)은 지금처럼 짧게. (클라이언트 보강 2026-11-09)
- (v1.7) **같이 놀기도 일정과 같은 따뜻한 해요체**, 상대를 "○○님"으로 부른다: "준호님 차례예요", "내 차례예요", "다섯 개를 이었어요", "아쉽게 졌어요. 한 판 더 할까요?", "준호님이 다음에 하재요". 진 사람·거절·만료 문구는 탓하지 않고 다음 행동을 권한다. 승패 문구에 조롱·과한 감탄(ㅋㅋ, 완패 등)은 쓰지 않는다.
- 숫자 단위는 항상 붙인다: "3건", "멤버 2명", "5개까지".
